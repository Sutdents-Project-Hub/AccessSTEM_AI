HOW IT WORKS

Supplied facts in, labelled answers out

1 · Learner or teacher

Picks a lesson, a learning mode and preferences: pacing, depth, math level, language.

2 · Web app

Next.js with semantic HTML, keyboard-first controls and a high-contrast toggle.

3 · Server route

Validates input, limits size and keeps the API key on the server.

4 · OpenAI API

Prompt V3 plus a strict JSON schema. Model gpt-6.1-terra, low reasoning effort.

A · Supplied graph facts

Formula, axes, units, key points, trends and an explicit list of unknowns. Sent with every request.

5 · Structured answer

Summary, sections, claims tagged given, derived or unknown with source IDs, and at most one next question.

6 · Safety checks

Source IDs validated, stray markup removed, provider errors (429, 502) shown honestly instead of faked.

No database

No login

Conversation lives only in the open page

Candidate lessons labelled “Teacher review pending”

Architecture as built in the web/ component; no mock answers are shown when the provider fails.

Walk through left to right. The important design choice is box A: the model never has to read a picture or guess a scale, because facts arrive as structured data. Box 6 is why a failed API call shows an error instead of a plausible fake answer.
